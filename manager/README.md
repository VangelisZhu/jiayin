# 家音曲库管理

可选 NAS 网页后台：只读体检、歌曲与专辑标签、合唱关系、歌词编码预览、AI 建议、批量应用、目录迁移和按批次回退。普通家音播放仍通过 OpenSubsonic 工作，不要求安装后台。

首版一个实例绑定一个音乐根目录和一个 Navidrome 账户。不同权限的账户使用独立实例。请先用生成曲库或副本验证；实际模型质量、NAS 权限和真实曲库迁移需要另行验收。

## Docker 部署

1. 把本目录放到 NAS 独立应用目录；复制 `.env.example` 为 `.env`。
2. 填写实际音乐路径 `MUSIC_PATH`、独立后台数据路径 `DATA_PATH`，以及至少 12 位的唯一初始管理员密码。
3. 设置有音乐读写权限的 `PUID`、`PGID`。容器只调整后台数据目录所有者，不递归更改音乐目录权限；不要把音乐目录设置为 777。
4. 默认监听 `127.0.0.1:8780`。局域网访问时，把 `BIND_IP` 改为 NAS 的 LAN 地址；不需要开放公网管理端口。

```sh
docker compose up -d --build
```

打开 `http://你的NAS局域网地址:8780` 登录。初始密码以 scrypt 哈希保存；已有数据目录的密码不会因修改 `.env` 而重置。

旧版群晖 Docker 没有 Compose 项目入口时，可以在电脑构建并 `docker save` 导出镜像，在 NAS 的“映像 → 从文件添加”导入，再配置同样的挂载、端口和环境变量。各 CPU 架构以实际构建测试报告为准。

### Navidrome 连接与数据库备份

修改已连接的真实曲库前，必须只读挂载 Navidrome 数据目录，以 SQLite Backup API 建立并校验一致性备份。不会直接修改服务器数据库。

在 `.env` 增加 `NAVIDROME_DATA_PATH`，然后：

```sh
docker compose -f compose.yaml -f compose.navidrome-backup.yaml up -d --build
```

不要只挂载单个数据库文件；WAL/SHM 也可能是读取一致状态所必需的。后台运行账户需要能读取这些文件。数据库备份保存在私有数据目录的 `database-backups/`，不包含在无凭据的网页导出包中，应另行妥善保存。

在网页“连接与 AI 设置”填写 Navidrome **连接地址**及账户。**手机使用的音乐服务器地址**用于绑定家音账户空间，留空沿用连接地址；内外网地址不同时显式填写，不自动猜测或合并。

如果 Navidrome 仅监听宿主机 `127.0.0.1`，桥接容器的回环地址无法访问它。应使用 NAS 宿主网络部署后台，并把后台监听限制到本机或 LAN 地址；不必改变原音乐服务器的监听配置。

HTTPS 反向代理入口需设置 `JIAYIN_PUBLIC_ORIGIN`。Cookie 使用 HttpOnly、SameSite Strict；HTTPS 下启用 Secure。管理接口不开放跨域访问。

## 整理流程

1. **只读体检**：读取真实文件标签、路径及歌词；展示缺失、乱码、合唱和专辑版本疑点。“同名专辑待核对”不等于一定错误。
2. **记录基线**：核对文件与服务器歌曲 ID。接口路径可能是虚拟路径；配置只读数据库挂载时，使用实际相对路径、可见歌曲 ID、文件大小及时长交叉核对。无法确认的项通过歌曲的“身份”入口手动核对，不按同名自动关联。
3. **生成草稿**：选歌曲或专辑，编辑选中的字段。多位歌手、专辑歌手、曲风每行一项；关联署名和失效身份字段的变化也进入预览。
4. **预览并应用**：检查原值、建议值、来源及范围。建立恢复副本，在同目录暂存，校验解码后的音频后替换文件；不转码。
5. **扫描核对**：请求 Navidrome 扫描，核对原歌曲 ID、字段、收藏、播放次数及已有歌单顺序。失败项保留待处理，不虚报已迁移。
6. **目录迁移**：当前标签核对通过后，独立生成目录草稿。完成后再次扫描核对。

歌曲歌手与专辑歌手独立。合唱关联多位演唱者，不按 `&`、`/` 一律拆分乐队。原专辑、精选集、不同发行版本保留，不自动删除重复文件。语种、整理地区和多值曲风分别维护，地区作为整理分类。

目录模板：`专辑歌手/专辑名 [年份] [版本]/碟号-曲序 歌名.ext`。歌词随音频移动，共用封面复制后保留原件；更新根目录内 UTF-8 M3U/M3U8 的相对文件引用。重名、非 UTF-8 播放列表、跨文件系统或不支持硬链接的迁移会停止，不覆盖文件。外部播放器数据库和其他类型的路径引用需要另行核对。

### 歌词

支持外置 LRC 和常见嵌入歌词读取，保留已有翻译轨道。严格解码产生候选，但能解码不代表文字一定正确，应对照试听。已丢失字符不能靠编码转换恢复。

联网匹配向 LRCLIB 发送歌名、署名；展示候选专辑及时长。修正写入 UTF-8 同名 LRC，保留嵌入原词与翻译文件。需检查服务器 `LyricsPriority` 是否优先读取该文件；TTML、ELRC、YAML 等优先源不会被擅自覆盖。

网页支持试听时间轴。试听只把音频从 NAS 传到当前浏览器，不上传给 AI。

仅修改歌词的批次按修改前的服务器标签与 ID 核对，并检查收藏及歌单。原来就存在的标签差异保留待处理，不把歌词任务通过视为标签或目录迁移通过。扫描需要 Navidrome 扫描权限；日常账户无权限时，由服务管理员触发扫描，再回后台核对。

## AI 整理助手

配置自己的云端 API 基础地址、模型和密钥。支持 `chat/completions`，按供应商文档显式选择 JSON Schema 或 JSON 对象响应模式；两者经过同一证据校验。没有内置模型或共享密钥，密钥加密保存且不返回浏览器。

DeepSeek 官方服务可填写 `https://api.deepseek.com`、`deepseek-flash`，响应模式选择“JSON 对象”。后台对该官方入口使用非思考模式，将输出预算用于完整的结构化建议；仍执行同一套证据校验。其他兼容服务不自动附加 DeepSeek 参数。[接口文档](https://api-docs.deepseek.com/zh-cn/api/create-chat-completion/)

先选择 50–100 首典型样本。MusicBrainz 检索不超过每秒一次，缓存七天；核实歌手、曲风和发行细节会增加查询，速度取决于网络。模型只比较后端取得的资料，没有文件、检索或命令执行工具。

MusicBrainz 的限流、暂时性服务错误和连接失败最多尝试三次，保留成功查询的缓存。未知时长只作为待核对候选，不能支持写入。AI 付费请求不自动重试；被拒绝的建议在后台私有数据中保留原因和原始返回，避免为诊断重复付费。原始返回是未信任的数据，不能直接应用。

建议需引用真实候选，整项字段由同一候选支持，校验时长与版本标签。无来源、未知目标、字段越界或触及人工锁定的结果被拦截；模型自报置信度不作为执行依据。没有资料时保留未知。

默认只发送必要元数据、匿名文件标识和候选，不发送音频、真实路径、NAS 地址或登录信息。歌词正文默认不发送：需先在设置允许，再在歌词页主动使用“AI 比较原词与候选”。AI 只能选择已有候选的原文和时间戳，不能补写歌词。

默认累计调用上限 100 次、保守 token 预算 1,000,000、单次输出上限 1,500。请求前预留预算；超时、限流或不合法返回也保留预留量，避免盲目重试超支。只有填写单价后才估算金额，币种与填写价格相同，实际费用以供应商账单为准。

核对样本正确率和费用后，显式开启全库分析。一次最多选择 10,000 首，内部按十首分批。暂停在当前请求结束后生效，继续只处理未完成部分。额度不足时停止并保留已有草稿。

## 回退与恢复

- 文件任务逐项记录；重启后未完成任务暂停，需要主动继续。
- 部分迁移中断可继续或回退。回退检查后续修改冲突，不覆盖后来的编辑。
- 未写入的失效排队项可放弃，再重新体检和编辑。
- 应用前文件内容变化会停止该项。
- 日常备份整个后台数据目录，保护 `vault.key` 及加密凭据，不能公开分享。
- 网页导出包包含修改记录和原文件副本，排除凭据、密钥及 Navidrome 数据库；使用磁盘暂存，避免全量占用内存。

停止服务后，把恢复包导入新的空数据目录：

```sh
python -m jiayin_manager restore jiayin-recovery.zip /path/to/new-empty-data
```

导入不会立即覆盖音乐文件。重新配置密码与连接，检查后执行回退。恢复 Navidrome 数据库应先停止 Navidrome 并保留现状，由管理员单独恢复；后台不覆盖运行中的数据库。

更换管理员密码并撤销已有会话：

```sh
docker compose exec manager python -m jiayin_manager password /data
```

## 连接家音 Android

网页设置生成只读连接码，在家音“设置 → NAS 曲库管理 · 共享分类”填写地址和连接码。验证服务器与账户一致后，读取已核对歌曲的共享地区、语种及版本信息。

个人歌手和目录分类优先，可恢复默认使用共享分类。普通播放、收藏、歌单与下载仍走音乐服务器。退出账户清除只读连接码；重新生成会撤销旧码。后台暂不可达时，曲库同步保留上次共享分类。

## 开发与测试

```sh
python -m venv .venv
# 激活虚拟环境后执行：
pip install -r requirements-dev.txt
python -m jiayin_manager demo /path/to/empty-demo-music
```

设置 `JIAYIN_MUSIC_ROOT`、`JIAYIN_DATA_ROOT`、`JIAYIN_ADMIN_PASSWORD`，再运行：

```sh
python -m jiayin_manager serve
pytest -q
node --check jiayin_manager/static/app.js
```

压缩格式完整性检查需要 FFmpeg，可设置 `JIAYIN_FFMPEG` 指定程序。服务器默认只监听本机，生产只运行一个 Uvicorn worker。测试使用合成音频和原创示例歌词；不包含个人曲库、真实 API 密钥或付费模型质量承诺。

本模块沿用仓库 GPL-3.0；Mutagen、FFmpeg 等保留各自许可证。外部资料与歌词按服务条款、许可及限速使用。
